打开 `demo/index.html`，右上工具条：`🔌 AI 通道状态`｜`🩺 自检`｜`🎬 导览`｜`− / N人 / ＋`｜`🔄 重置`｜`▶ 自动演示`

| 页面 | 能力 | 关键点 |
|---|---|---|
| 首页 | 创建房间（旅行名/目的地/日期/人均预算）、加入房间（6 位房间号） | 真实增删，多机同步可见 |

## 2. 代码地图

```
demo/index.html                    唯一交付物（≈1500 行，HTML+CSS+JS 单文件）
├─ <style>                         黑白杂志风设计系统（Space Grotesk + 细分隔线 + 大数字）
├─ HTML                          工具条 / 手机舞台 / 提示
└─ <script>                      全部逻辑，分区如下：
   ├─ State / USERS               数据与用户模型（每台手机 = 一个 user 对象）
   ├─ V3 共享内核适配层            AI/CTRIP 挂载、CURRENCIES、money/billCNY/rateOf/makeBill、probeEngine
   ├─ renderPhones / renderApp    手机渲染 + 页面路由（home/room/add/capture/settle/stats）
   ├─ renderHome / renderRoomDetail / renderStats
   ├─ renderAddBill + AI 记帐交互  aiParseBill / aiUseSample / startVoiceInput / selectCurrency
   ├─ renderCapture + 票据         ocrSelectType / ocrStartScan / ocrToggleItem / ocrImport
   ├─ renderOrderTab + 携程订单    orderUseSample / orderParse / orderToggle / orderImport
   ├─ visionRecognize/visionImport 订单截图识别（在线实时 / 离线样例）
   ├─ renderSettle / calcSettlement 结算与最简转账；genNarrative/copyReport
   ├─ 导览引擎                     TOUR_STEPS(8) / startTour / tourNext / toggleTourAuto
   └─ 自检引擎                     runSelfTest(13) / runTourTest / showTestPanel

apps/miniprogram/utils/ai.js       ⭐ 共享 AI 内核（UMD）：解析/分类/分摊/折算/审计/预算/统计/洞察/小作文
apps/miniprogram/utils/ctrip.js    ⭐ 携程订单内核（UMD）：订单文本 → 结构化订单 → AA 账单
apps/miniprogram/utils/settle.js   结算算法（贪心最简转账）+ 分享文案
apps/miniprogram/pages/*           小程序 5 个页面（index/room/add-bill/settle/history）
apps/cloudfunctions/*              9 个云函数（login/createRoom/joinRoom/addBill/deleteBill/ocr/settle/initDB/removeMember）
server/app.js                      可选后端（Express + SQLite）：房间/账单 REST + /api/ai/* 增强接口
tests/*.js                         三套自动化测试（见第 3 节）
```

> **重要**：算法只写在 `apps/miniprogram/utils/` 一处，Demo 与 server 通过 `<script src>` / `require` 复用。
> 改算法 = 改一个文件，三端同时生效。**不要**在 Demo 里另写一份业务算法。

## 4. AI 能力与「AI 通道」

### 默认（离线，零配置）

- 一句话解析、分类、分摊、多币种折算、审计、预算、统计、洞察、小作文：**全部由本地规则引擎完成**，毫秒级、不联网、不需要 Key。
- 票据/订单截图：内置样例演示同一条识别流水线，结果**明确标注为「内置样例」**。

### 可选增强（自备 Key，与前任无关）

在 `server/.env` 里配置（参考 `server/.env.example`），启动后端后 Demo 右上角徽标会变成 `☁️ AI 已连接`：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1   # 任何 OpenAI 兼容接口均可
LLM_MODEL=deepseek-flash
VISION_MODEL=deepseek-flash
DEEPSEEK_API_KEY=你的Key                    # 也可用环境变量注入，勿写入仓库
NPU_FALLBACK=0                              # 本机端侧模型回退开关（可选）
```

**行为约定**：Demo 通过 `GET /api/ai/engine` 探测通道；探测失败/超时（1.5s）→ 显示「🔌 离线模式」，
所有功能照常可用（`fetch` 在 `file://` 下受限属正常现象，不代表故障）。

## 5. 已知限制与坑（请务必先读）

| # | 坑 / 限制 | 说明与建议 |
|---|---|---|
| 1 | **多机同步是单页模拟** | 4 台手机都在同一个页面里、共享一份 `State`，「同步」是本地重渲染，不是真实网络同步。要做真实多人，需接 server 的房间接口 + WebSocket/轮询 |
| 2 | **小程序端 UI 未与新 Demo 统一** | `apps/miniprogram` 是小程序原生页面，视觉仍是旧版；如需统一，按 `demo/index.html` 的设计语言重写 wxss |
| 3 | 无鉴权 | server 与云函数均为 Demo 级，没有登录态校验/权限体系，**不要直接暴露到公网** |
| 4 | `file://` 下 fetch 受限 | 所以 AI 通道探测基本会失败 → 走离线模式，这是预期行为。要联网能力就把 Demo 放到 http 服务下 |
| 5 | 浏览器缓存 | 改完 `demo/index.html` 后如看到旧界面，用 **Ctrl + F5** 强刷 |
| 6 | 语音输入依赖浏览器 | Web Speech API 在部分浏览器/内核不可用；代码里已有降级提示（不会报错） |
| 7 | 账单时间与统计 | 统计按 `bill.createdAt` 聚合，历史数据若无该字段会被跳过；新增账单统一走 `makeBill()` 生成 |
| 8 | 不要提交 `server/.env` 与数据库 | `.gitignore` 已忽略 `.env`、`server/data/`、`*.db*`；`server/data/` 由程序自动创建 |
| 9 | 微信云函数 `ocr` | 需要自己申请腾讯云 OCR 的 SecretId/Key 才能真跑（见 `docs/部署与配置.md`） |

## 6. 建议的下一步（按优先级）

1. **真实多人房间**：把 Demo 的 `State` 换成对 server 的读写（`/api/rooms*`、`/api/bills*` 已就绪），加轮询或 WebSocket，让 4 台手机变成 4 个浏览器窗口/真机。
2. **小程序端与新视觉统一**：设计师风格已定（黑白杂志风），照着 `demo/index.html` 的 token 改 wxss，工作量可控。
3. **AI 通道产品化**：把 `server` 的 `/api/ai/parse|vision` 接成一个可用服务（鉴权 + 限流 + 超时 + 计费保护），小程序端接入同一接口。
4. **携程开放平台对接**：申请授权后，把「粘贴订单」升级为「自动拉单」（数据管线与字段映射已具备，见 `ctrip.js`）。
5. **工程质量**：加 CI（跑三套测试 + 无头 `#selftest`）、把 Demo 单文件拆成模块（若继续变大）、补 E2E 用例。
6. **答辩材料补齐**：`docs/竞品分析与差异化.md` 已有素材，可再补一页「技术亮点 → 现场演示动线」的对照表。

## 7. 红线与表述规范

- ❌ 不要依赖前任的服务器、API Key、本机模型环境；演示必须能在**别人的电脑上、离线**跑通。

- ❌ 不要说「已接入携程系统」。正确表述：**订单入账管线已打通，自动拉单需携程开放平台授权（对接点已预留）**。

- ✅ 可以说：本地规则引擎离线可用、多币种结算账恒平、贪心最简转账、AI 审计与洞察、三端共享一份算法内核。
