# TravelAA 参赛扩展完善方案（V2）

> 目标赛事：**携程首届高校 AI HACKATHON 大赛**
> 方案定位：把"能用的 AA 记账 demo"扩展为 **"AI 深度可答辩、产品闭环可体验、携程生态可叙事"** 的参赛级作品
> 执行方式：本文档为总纲，按阶段逐步实施；每阶段有验收标准，实施记录见文末执行台账

---

## 一、为什么"现在的设计对参赛来说太简单"

| 维度 | 现状 | 评委视角的风险 |
|---|---|---|
| AI 深度 | 规则引擎 NL 解析 + OCR；LLM 接口是占位 | "这算 AI 吗？就是正则 + CRUD" |
| AI 广度 | 3 个能力点（解析/OCR/洞察）且洞察较浅 | 亮点单薄，撑不起 3 分钟演示 |
| 产品闭环 | 账单只能加不能改；成员不能管理；无预算 | "半成品" |
| 场景真实度 | 东京行用人民币记账；无汇率 | 故事经不起追问 |
| 携程契合 | 仅口头叙事 | 最关键的"赛道契合"分拿不到 |
| 工程可信度 | 测试 62 项、无新特性测试 | 追问即露怯 |

结论：参赛需要的不是"再加一个页面"，而是 **AI 能力矩阵 + 产品闭环 + 生态叙事** 三条线同时加深。

## 二、扩展后的作品定位

> **TravelAA —— 结伴旅行的 AI 记账官：会听、会看、会读单、会算账、会复盘**
>
> 五层 AI 能力矩阵（全部落在这次扩展中）：
> 1. **会听**：语音/口语文本归一化 → 一句话记账（中文数字、口语量词归一）
> 2. **会看**：票据 OCR → 结构化账单（保留并加固）
> 3. **会读单**：携程行程订单（机票/酒店/门票）一键导入自动入账 —— **携程生态强叙事**
> 4. **会算账**：多币种汇率折算 + 贪心最简转账 + 尾差安全分摊（账恒平）
> 5. **会复盘**：AI 账单审计（重复/异常/漏分摊检出）+ 预算燃烧预警 + 每日消费分析 + 旅行报告
>
> 并且全部能力 = **规则引擎（离线保底）+ LLM 双轨（配置即升级）**，现场演示永不翻车。

## 三、能力矩阵与技术设计

### 3.1 多币种结算（场景真实度：东京行改用日元记账）

- 账单增加 `currency` / `rate`（记账时快照汇率，避免结算漂移）/ `cnyAmount` 字段
- 结算统一折算 CNY：`balance += amount * rate`
- `ai.js` 提供 `toCNY(amount, currency, rates)`、`allocateEvenly` 保持原币分摊、结算端折算
- 汇率表可被 `options.rates` / `setRates()` 覆盖（接汇率 API 的口子）

### 3.2 LLM 双轨真正接通（AI 深度：可答辩）

- `ai.js#parseWithLLM` 强化：结构化 system prompt + few-shot + JSON 修复（容错 ```json 包裹/尾逗号/中文冒号）+ 与规则引擎结果融合（LLM 高置信字段覆盖，规则结果保底）
- `ai.js#buildLLMPrompt` 输出可直接贴给任意 OpenAI 兼容接口
- server 新增 `POST /api/ai/parse` 的 `mode:'llm'`：读 `LLM_API_KEY`/`LLM_BASE_URL`/`LLM_MODEL`，用 fetch 调 OpenAI 兼容接口；无密钥/失败自动回退规则引擎并标注 `source`
- 新增 `POST /api/ai/narrate`：LLM/模板双轨生成"旅行消费小作文"（报告的加分项）

### 3.3 AI 账单审计（AI 广度：新能力）

`ai.js#auditBills(bills, members)` → 检出问题清单 + 严重度 + 建议：
- **重复账单**：同金额+同说明+相近时间（<10min）疑似重复录入
- **异常大额**：单笔 > 均值 * k 且 > 阈值，提示复核
- **漏分摊**：splits 合计 ≠ 账单金额（账不平）
- **疑似漏记**：成员垫付占比异常 / 连续多天无记录（可选）
- **分类置信度低**：category=other 且金额较大，建议人工归类

### 3.4 预算管理 + 每日消费分析（产品闭环）

- `ai.js#budgetStatus(bills, members, budget)`：
  - 总预算/人均预算、已花/剩余、进度百分比
  - **燃烧率**：按行程天数推算"按当前速度会不会超支"（forecast），超支预警与"安全日均"
- `ai.js#dailyStats(bills)`：按天聚合（含星期）、日均、最贵一天、分类按天分布

### 3.5 携程订单导入（赛道契合：核心叙事）

新模块 `apps/miniprogram/utils/ctrip.js`（UMD，三端复用）：
- `parseOrderText(text, members, meName)`：把订单确认文本（短信/复制的订单页）解析为订单结构
  - 识别类型：机票/酒店/火车票/门票/租车；提取订单号、日期、金额、商品名、出行人
- `orderToBill(order, members, options)`：订单 → 账单草稿（分类映射、分摊默认全员、付款人=下单人）
- `CTrip_SAMPLES`：内置 3 类示例订单（东京机票/酒店/迪士尼门票），演示一键导入
- 服务端 `POST /api/ctrip/import` + 小程序/演示页"从携程订单导入"入口

### 3.6 语音记账管线（AI 广度：新能力）

- `ai.js#normalizeSpeech(text)`：口语文本归一化
  - 中文数字金额："八十六块"→"86元"、"三百二十八"→"328"
  - 语音同音/口语词："AA制"、"平摊一下"、"我垫付的"归一
- 小程序端接微信同声传译插件（`record` → 文本 → `parseBillText`），插件未配置时降级为手动文本输入；demo 端用 Web Speech API（不支持时降级）
- 归一化后走同一 NL 解析管线 —— 复用而非重写

### 3.7 产品闭环补齐

- **账单编辑**：add-bill 页支持 `billId` 编辑模式（预填、原地更新）；server `PUT /api/bills/:id`；云函数 addBill 支持 edit
- **成员管理**：房间页移除成员（有未结清余额时禁止并提示）、改昵称
- **预算设置**：房间页设置总预算，进度条 + 预警
- **结算闭环**：结算页"标记已结清"（写 `settledAt`），历史页可看结算记录
- **历史增强**：分类筛选、编辑/删除、审计问题角标

### 3.8 工程与演示

- 测试：新增 `tests/v2.test.js` 覆盖全部新能力（多币种/LLM 回退/审计/预算/订单解析/语音归一化/结算折算），原 62 项保持全绿
- demo：主 demo 增加预算条、AI 审计卡片、订单导入、多币种展示；showcase 增加审计扫描演示
- 文档：README（能力矩阵、架构图）、优化文档执行台账、演示脚本（3 分钟版 + 新增段落）

## 五、演示叙事升级（3 分钟 → 五层 AI）

1. **会听**：语音/一句话"打车去机场八十六块我垫的和小红小李平分" → 归一化 → 解析填表
2. **会看**：拍支付宝截图 → OCR 出金额商户时间
3. **会读单**：粘贴携程订单文本 → 一键导入机票/酒店/门票三笔账（携程叙事落点）
4. **会算账**：东京行 JPY 记账 → 汇率折算 → 贪心 3 笔转账收尾，账恒平
5. **会复盘**：AI 审计揪出 1 笔疑似重复 + 预算燃烧预警 + 旅行消费报告一键分享

演示保险：全部能力离线规则保底；LLM 仅是"锦上添花"，断网/无密钥同样全流程可跑。

## 六、风险与边界

| 风险 | 应对 |
|---|---|
| 范围太大做不完 | 按 S1→S8 顺序实施，测试为每阶段闸门；S4-S7 可裁剪展示但内核必须完整 |
| LLM 不稳定 | 双轨回退，演示永远走规则引擎路径也可讲 |
| 汇率不准 | 记账时快照 `rate` 字段，展示"记账汇率"，并保留可配置口子 |
| 订单文本格式多变 | 解析器多正则 + 宽松容错 + `needManual` 标记，示例订单兜底 |
