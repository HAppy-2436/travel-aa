# 🧯 演示健壮性与可用性自查（第十二轮）

> 起因：用户实测撞到三个问题 ——
> ① 演示模式下「退出演示」和「暂停」**叠在一起**；
> ② 点「导览」后按 Esc，「直接没了，网页卡住了」；
> ③ 点「导览」时**下面的自动演示还在一直走**。
>
> 要求不只是修这三处，而是：**假设自己是完全不会用这个页面的评委**，
> 把演示与功能上的问题全面查一遍，并把同类 bug 彻底自查掉。
>
> 所以本文分两部分：**根因清单**（每一条都先复现、再修、再固化为测试）
> 和 **零基础走查**（一个不知道点哪的评委会卡在哪里）。

---

## 一、三个 bug 的根因（全部先复现再动手）

复现手段：`tests/tools/repro-modes.js`（jsdom 真跑页面、真派发键盘事件），
修复后同一脚本回跑，三条全部从 `REPRODUCED` 变 `fixed`（该工具已入库，改演示逻辑后可随时回跑）。

### ① 「退出演示」与「暂停 / 下一步 / 速度」叠在右上角

| | |
|---|---|
| **现象** | 演示模式右上角两个控件叠在一起，字压字（用户截图） |
| **根因** | **两块 fixed 元素抢同一个角**：`.present-exit`（`position:fixed;top:14px;right:18px`）是第 10 轮加的独立按钮；解说栏 `.pshow` 是整行 fixed，它的右端本来就排着「速度 / 下一步 / 暂停」。后加的那个按钮没人检查过和已有控件的关系 |
| **修** | **一个角只能有一个主人**：删掉独立按钮，把「✕ 退出」并进 `.pshow-top` 这一行 flex 的末尾。现在是同一个容器排版，**结构上不可能重叠** |
| **闸门** | `demo.check.js`：不得再出现 `present-exit`；`#presentExit` 必须在 `.pshow-top` 内且在 `.pshow-narr` 之前 |

### ② 导览中按 Esc →「直接没了，网页卡住了」

| | |
|---|---|
| **现象** | 整页变黑、什么都看不见，点鼠标也没反应 |
| **根因** | 那个变黑的东西是导览遮罩 `.tour-mask`：`box-shadow:0 0 0 9999px rgba(8,8,12,.74)` —— **它把整页压暗，只留一个"洞"高亮目标**。<br>导览的每一步是**延时 260ms** 才渲染的（先滚进视口、再量位置）。Esc 如果落在这 260ms 窗口里：`tourExit()` 先把遮罩和卡片都隐藏了，**随后那个已经排好队的旧回调又被执行**，它把 `mask.style.display='block'` 写回来 —— 但卡片不会回来（回调里没有显示卡片的代码）。于是：**遮罩全屏压黑 + 导览卡是隐藏的**，而遮罩是 `pointer-events:none`，所以点得动但什么都看不见 = "卡住了" |
| **修** | 两层防御：<br>① **代次令牌 `tourGen`**：每次进出导览 `tourGen++`，延时回调第一句就是 `if (myGen !== tourGen) return;` —— 过期回调一律不碰 DOM；<br>② **CSS 兜底**：`body:not(.touring) .tour-mask,body:not(.touring) .tour-card{display:none!important}` —— 没有 `body.touring` 就绝不允许遮罩可见，"有遮罩没卡片"的黑屏在结构上不可能出现 |
| **闸门** | `demo.check.js` 检查令牌与 CSS 兜底都在；页内 `#uitest` **新增实测**：故意在 80ms（窗口内）派发 Esc，等 420ms（跨过窗口）再断言遮罩和卡片**同时**关闭。 |

> ⚠️ **这条最值得记的教训**：上一轮我**已经有**一条"导览可用 Esc 收起"的断言，
> 但它只检查了 `tourCard.style.display === 'none'` —— 而 bug 出在**遮罩**上。
> **断言写得太窄，等于没测。** 现在这条断言同时覆盖卡片、遮罩和 `body.touring`。

### ③ 点导览时自动演示还在跑

| | |
|---|---|
| **现象** | 导览卡片在讲第 3 步，顶部分镜进度却在 ② / ③ 之间自己跳；手机画面也在自己切 |
| **根因** | `present` / `touring` / `autoRunning` 是三个**各自为政**的开关：`startTour()` 只加了 `touring`，没人管正在跑的自动演示（它是一条 `await` 长链，只有 `stopAutoDemo()` 能取消） |
| **修** | **互斥**：`startTour()` 第一句 `stopAutoDemo({ keepPresent: true })`（只停演示、不退出演示模式）；`autoDemo()` 第一句 `tourExit()`。为此给 `stopAutoDemo` 加了 `keepPresent` 开关 |
| **闸门** | `demo.check.js` 检查两个方向；页内 `#uitest` 实测：先跑演示再点导览，断言 `autoRunning === false`；反方向断言不留遮罩 |

### 顺带修掉的同类问题（自查出来的）

| 问题 | 根因 | 修 |
|---|---|---|
| 导览开着时点「退出演示」→ 遮罩 + 卡片浮在常规页面上 | `exitPresent()` 只管 `present`，不管导览 | `exitPresent()` 先 `tourExit()`；退出按钮改走 `exitAllModes()`（一次收干净 present / touring / 自动演示） |
| 自动演示跑到一半点「🩺 自检」→ 面板背后画面还在自己动 | `runSelfTest()` 不管模式 | `runSelfTest()` 开头 `exitAllModes()` |
| Esc 在"导览 + 手机弹窗"同时开着时，一下把整个导览掐掉 | `A11Y_LAYERS` 按 z-index 排序，导览卡（210）排在手机弹窗（60）前面 | 改成按**"谁真的挡着页面"**排序：全屏弹层 → 手机弹窗 → **导览卡放最后**（它是讲者提示条，不阻断页面） |
| 导览卡片正好盖住它自己高亮的那块 | 卡片固定在底部居中，没和"洞"的位置对过 | 用卡片**真实占位**与目标矩形做相交判断；**只有"翻到顶部确实躲得开"时才翻**（像 `#phonesStage` 这种占满整屏的目标，翻上去照样压着，来回跳反而晃眼） |

**导览全步骤实测（真实浏览器 + JS 量布局）**：
`tests/tools/audit-tour.js` 逐步跑完 15 个导览步骤，报告目标是否可见 / 是否在视口内 / 高亮框是否包住目标 / 卡片是否盖住目标。
（`node tests/tools/audit-tour.js 1280 720`，可传视口宽高；不进 CI，因为要起 Edge。）

```
1440×900  → 15 步全部通过
1366×768  → 15 步全部通过
1280×720  → 15 步全部通过（投影仪常见分辨率）
1024×640  → 3 处残留重叠，均为"翻上去也躲不开"的必然重叠（已实测确认）
```

## 二、零基础评委走查（假装完全不会用）

按"打开页面 → 我该点哪 → 点错了怎么办"的顺序走一遍，改掉卡点：

| # | 走查发现 | 修 |
|---|---|---|
| 1 | **不知道从哪开始**：首屏是 4 台"还没有旅行房间"的空手机，唯一的入口「▶ 自动演示」混在工具条 5 个按钮中间 | 解说条待机态直接给**两个入口**：`▶ 播放完整演示`（**实心品牌橙**，唯一强调）+"逐步导览（15 步）"；待机文案改成"按钮叫什么就说什么"，不再出现"点「▶ 自动演示」"这种对不上的指路 |
| 2 | 待机时「⏭ 下一步 / ⏸ 暂停 / ⏩ 速度」就在那儿，**点了没反应** —— 最容易被当成"页面坏了" | 只有一组按钮会显示：`body.idle` 时显示**入口**，播放中才显示**播放控制**。死按钮根本不出现 |
| 3 | 不知道下面还有东西（评委区在第 5000px 处） | 提示条补一句：`↓ 往下滚：和别家不一样的三个点 / 验收证据 / 诚实边界` |
| 4 | 讲者要一只手翻页，鼠标换页很别扭 | 导览支持 **← → / PageUp / PageDown** 翻页，卡片上直接写着「← → 方向键翻页 · Esc 退出」 |
| 5 | 演示结束/中断后不知道还能重来 | 退出后自动回到待机态 → 两个入口又出现（`syncModeUi()` 统一状态） |
| 6 | 演示模式下解说栏在窄屏可能折行，把手机挤矮 | `≤1240px` 时品牌副标题隐藏，先让位给控制按钮 |

## 二之二、第二轮走查：**真的按"完全不会用"的顺序点一遍**

上面那一轮靠的是"看"，这一轮改成"做"：写了一个走查工具 `tests/tools/judge-journey.js`，
把评委从落地到走完全流程的 **20 个动作真的做一遍**（按可见文字点击、真派发键盘事件），
每一步都截屏并抓"此刻页面上能点什么"，再看卡在哪。
它抓出了 6 个上一轮**没看到**的障碍——因为上一轮我只看了截图，没有真的点。

| # | 走查发现（都是真实点击的结果） | 根因 | 修 |
|---|---|---|---|
| 1 | **退出导览后走进死路**：评委点导览卡「退出」，页面停在"铺满一屏"状态，而 `present` 下工具条是**隐藏**的 → 后续按真实文字点「自检 / 重置 / 创建房间」**全部"点不到"** | 导览会 `enterPresent()`，`tourExit()` 却只摘 `touring`，没人负责把 `present` 收回去 | 拆成 `tourTeardown()`（只收拾导览）+ `tourExit()`（用户退出导览时**一并离开铺满一屏**，回到有工具条的常规页）。`exitPresent/exitAllModes` 改用 `tourTeardown` 避免绕圈 |
| 2 | **导览期间顶部有一套"点了没反应"的按钮**：浮动栏显示「⏭ 下一步 / ⏸ 暂停 / ⏩ 1×」，而它们是**自动演示**的控制器（`autoRunning` 此时是 false）→ 点了什么都不发生；同时还和导览卡上的「下一步 →」**重名** | 顶部浮动栏只按"待机/播放中"两态切按钮，没考虑第三种"导览中" | `body.touring .pshow-play{display:none}`：导览期间顶部只留品牌 / 进度 / 退出，控制权归导览卡（一套按钮，不重名、不失效） |
| 3 | **铺满一屏里找不到"结论与验收"**：`body.present .judge{display:none}`，而提示条又叫评委"往下滚"（提示条本身在 present 下也是隐藏的） | 评委区只在常规态存在，铺满一屏是个封闭世界 | 浮动栏加一条 `↓ 结论与验收` → `jumpToJudge()`：退出铺满一屏 + 滚到 `#judgeSection` |
| 4 | **自检面板一打开就滚到底部**：评委看到一墙 `PASS`，**看不到标题、得分和"✅ 一切就绪，可以开讲"** | `a11yOpen()` 聚焦"第一个可聚焦元素"，而面板里唯一可聚焦的是最下面的「关闭」按钮 → 浏览器把聚焦元素滚进视野 | 聚焦前把 `scrollTop` 归零 + 用 `focus({preventScroll:true})`；键盘可达性不变 |
| 5 | **自检会"看状态脸色"**：评委看完演示中途按 Esc（房间已建、还没演到那笔日元），再点自检就红一项 —— 评委区那面数字墙显示 `21/22` | 「外币账单已按快照折算」这条查的是"房间里有没有外币账单"，是**数据**不是**能力** | 改成验能力：房间里没有就用 `makeBill()` 当场造一笔探针账单（不写 State）验证"外币会带人民币快照"。新增工具 `tests/tools/selfcheck-robustness.js` 在 5 种真实状态下各跑一次自检，现在全部满分 |
| 6 | **首屏是 4 台空手机**：旅行 AA 的价值（分摊 / 多币种 / 结算 / 私账）在空态里一点都看不到；想摸到真东西得先手工建房、再手工记 5 笔账 | 冷启动没有任何播种 | 冷启动自动铺一桌样例数据（房间 + 5 笔账含外币 + 4 台手机入伙），解说条写清"已铺好样例，想看空态点「🔄 重置」"。**有旧数据（localStorage 回填）或带演示/自检 hash 时不播种**，保证可复现 |

另外顺手修的：

| 发现 | 修 |
|---|---|
| 评委区标题被 sticky 工具条压住（锚点跳转后） | `.judge{scroll-margin-top:62px}`；`jumpToJudge()` 再加"350ms 没到位就直接跳"的兜底（平滑滚动在无头 / 减少动态效果下可能不动） |
| 托管到 https 后每次打开都请求 `http://localhost:3000` | 会被浏览器按**混合内容**拦掉：结果一样是离线，却在控制台留一条红色报错 → `location.protocol !== 'http:'` 时直接不探测 |
| 同一个动作两个名字：工具条「▶ 自动演示」vs 解说条「▶ 播放完整演示」 | 统一成 **「▶ 播放演示」**（工具条 / 解说条 / 浮动栏 / 收官页重播全部一致），待机文案跟着改 |
| 「⛶ 一屏演示」是行话 | 改名 **「⛶ 铺满一屏」**，说清它干的是"不用滚动鼠标" |
| 提示条让评委"直接点手机自己试"，但手机里是空的 | 待机入口加第三个 **「自己上手」**（= 铺样例数据），与「播放演示 / 逐步导览」并列 |

**走查结论**：20 个动作现在**全部点得到、全部有反馈**，零 `点不到` 警告。

## 四、明确不做（这一轮想过但决定不做）

| 项 | 为什么不 |
|---|---|
| 评委点手机时自动暂停演示 | 需要一个"这是用户点的、那是脚本点的"判别通道，要动所有手机内事件的入口；收益不抵风险，先用「⏸ 暂停」这个明确按钮 |
| 把导览卡做成可拖拽 | 避让问题已经用几何判断解决，拖拽只增加状态 |
| 遮罩去掉 `box-shadow:0 0 0 9999px` 改画四个矩形 | 四矩形要同步四处位置，反而更容易出"半开"bug；现在用 `body:not(.touring)` 兜底更稳 |

> 原则不变：**只认可复现的证据**。这一轮每一条修复都先有一个可复现的脚本，
> 修完再看它变绿；页内断言覆盖真实 DOM 状态，而不是只看文案。
