## 七、导览（`🎬 导览`）的用法

**15 步**（同类功能合并），覆盖 **40 项功能**，两侧都受守卫：

- 每步用 `covers: [...]` 声明讲到了哪些功能，`tourCoverage()` 双向校验
  （清单里有但导览没讲 = 漏；导览讲了但清单里没有 = 脏），结果进 `#selftest`。
- `#tourtest` 逐步执行每步的 `before()`，要求高亮目标**真实存在且可见**（复现演示模式 + touring）。
  过去只查"元素存在"，于是 `body.present` 把工具条设为 `display:none` 时，
  前几步的"高亮演示台"其实是**高亮到空气**，测试照样绿。
- 每台手机至少 3 个导览环节（`#selftest` 与 `#tourtest` 都查），避免再出现"第 4 个人啥都不干"。

**演示增强参数**（可直接用于答辩/录屏）：

| 打开方式 | 效果 |
|---|---|
| `demo/index.html?n=4#auto` | 4 台手机开场并**自动开演**（24 个分镜） |
| `demo/index.html?n=4&stage=10#auto` | 自动演示**定格在第 10 步**（智能抹零），便于讲解/截图 |
| `demo/index.html?n=4&tour=13` | 导览**直接停在第 13 步**（一键清账 + 结清闭环），便于反复讲某一步 |
| `demo/index.html#v3demo` | 直接进入 V3 功能场景（北海道滑雪行），可手动点 |
| `demo/index.html#tourtest` | 17 项：15 步高亮 + 功能覆盖 + 每台手机都有环节 |
| `demo/index.html#uitest` | 跑 101 项真实点击交互验收（含无障碍 / 结算闭环 / 4 台手机都动手） |
