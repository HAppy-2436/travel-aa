# 🎨 UI 排版规范（问题诊断 + 改版方案）

> 起因：用户反馈「UI 排版有点丑」，并进一步定位为**「又太稀又太挤」「层次乱」「演示台丑」**。
> 本文是**先出方案、不动代码**的产物。审完再实施。

---

## 一、先量化：问题到底在哪

用 jsdom 实测 demo 六个页面，统计**间距取值种类**与**字号取值种类**：

| 页面 | 一级区块数 | 间距用到几种值 | 字号用到几种值 |
|---|---|---|---|
| home | 4 | 8 | 8 |
| **room** | **17** | **12** | **15** |
| add | 6 | 7 | 6 |
| capture | 3 | 4 | 3 |
| settle | 21 | 10 | 12 |
| stats | 21 | 11 | 11 |

实测用到的具体值：

```
room  间距: 1, 2, 5, 8, 9, 10, 11, 12, 13, 14, 16, 18
room  字号: 8.5, 9, 9.5, 10, 10.5, 11, 11.5, 13.5, 14, 14.5, 15, 15.5, 16, 19, 23
stats 间距: 4, 5, 6, 7, 8, 9, 10, 12, 13, 14, 18
stats 字号: 9, 9.5, 10, 10.5, 11, 12, 13, 14.5, 15, 19, 23
```

### 结论：三个根因

**根因 1｜间距没有网格**：8~12 种间距值，且**相邻只差 1px**（8/9/10/11/12/13/14）。
人眼根本分辨不出 9px 和 10px 的差别，结果是"到处都不一样，又说不出哪里不对"——这就是**"乱"**。

**根因 2｜字号阶梯太碎**：15 种字号，其中 `9 / 9.5 / 10 / 10.5 / 11 / 11.5` 六级挤在 2.5px 内。
没有层级对比 → 读者找不到重点 → 这就是**"糊"**。
同时正文主力在 9.5~11px，**偏小**，这是**"小字太多"**。

**根因 3｜分区无节奏**：
- 房间页 **17 个一级区块**挤在 640px 滚动区，平均每块 37px → **"挤"**
- capture 页只有 **3 个区块** → **"稀"**
- 相关的内容（预算条/数据格/备注）彼此间距与不相关内容一样 → 眼睛不知道该把什么归为一组

> 所以「又稀又挤」并不矛盾：**是"该挤的地方不挤、该松的地方不松"**。

## 二、改版方案

### 2.1 间距：建立 4pt 网格，只留 6 档

| 档位 | 值 | 用途 |
|---|---|---|
| `--s1` | 4px | 紧密：标签与它的值、图标与文字 |
| `--s2` | 8px | 同组内元素 |
| `--s3` | 12px | 卡片内边距 |
| `--s4` | 16px | 区块内边距 / 卡片间距 |
| `--s5` | 24px | 区块之间（有语义分隔） |
| `--s6` | 32px | 一级章节之间 |

**规则**：
- 组内间距 ≤ `--s2`，组间 ≥ `--s5`，**至少差 3 倍** → 形成"成组感"
- 禁止出现 1/2/5/9/11/13/14/18px 这些值
- 间距一律用变量，不再写行内 `style="margin-top:11px"`

### 2.2 字号：6 级阶梯，级间至少差 2px

| 级别 | 值 | 用途 | 字重 |
|---|---|---|---|
| `--t1` 主视觉 | 32px | 首屏 slogan、结算总金额 | 700 |
| `--t2` 大数字 | 22px | 统计格核心数值 | 700 |
| `--t3` 页面标题 | 17px | 手机内页标题、房间名 | 700 |
| `--t4` 正文 | **13px** | 账单名、成员名、正文（**主力字号，从 9.5~11 提到 13**） | 400/600 |
| `--t5` 辅助 | 11px | 时间、来源、次要说明 | 400 |
| `--t6` 标签 | 10px | 英文小字标签（BUDGET / TOTAL），字距 1.4px | 600 |

**规则**：
- **级间至少差 2px**，禁止 0.5px 级差（9/9.5/10/10.5 全部取消）
- 正文下限 **13px**（原 9.5px 太小）；标签下限 **10px**
- 主视觉上限 32px（海报级不超过 36px，`#uitest` 有守卫）

### 2.3 分区节奏：显式"组"的概念

每个页面拆成 3~5 个**语义组**，组间 `--s5(24px)`，组内 `--s2(8px)`：

```
【房间页】从 17 个平铺区块 → 4 个组
  组1 概览   ：标题 + 预算条 + 4 格数据          （组内紧凑，一组视觉整体）
  组2 备注   ：外币折算 / 我的私账（一行一条）    （轻量，不与组1 抢）
  组3 成员   ：成员胶囊
  组4 明细   ：审计结论 + 账单列表
```
- 视觉统一：一组内用同一张"卡"或同一条左对齐线，不再每个块都独立成盒
### 2.4 演示台（手机外面的壳）改造 —— 逐部位诊断

用户明确点名"电话外面的演示台丑"，这里逐条量化。所有问题都标注了代码位置。

#### 🔴 D1 顶部标题会折行，且与工具条挤在同一行

```html
<div class="hdr">                      <!-- display:flex; justify-content:space-between -->
  <div><h1>✈️ TravelAA · 多人实时联动演示</h1><p id="hdrSub">…</p></div>
  <div class="hdr-r">… 8 个按钮 …</div>
```
- `.hdr h1{font-size:24px; letter-spacing:-0.8px}`（第 15 行）
- 中文标题在 1360px 视口下**被压成两行**，与右侧工具条同一水平线 → 顶部高低不齐
- 实测（900px 视口截图）标题折成「TravelAA · 多人实 / 时联动演示」

**改法**：标题区与工具条**上下分两行**（标题独占一行）；标题加 `white-space:nowrap` 或字号随视口 `clamp(17px,2vw,24px)`。

#### 🔴 D2 工具条 8 个按钮视觉等重，找不到主行动

```html
<span class="cb" id="engineBadge">🔌 离线模式 · 本地规则引擎</span>
<button class="cb" onclick="runSelfTest()">🩺 自检</button>
<button class="cb" onclick="startTour()">🎬 导览</button>
<button class="cb" onclick="removePhone()">−</button>
<button class="cb act">📱 N人</button>
<button class="cb" id="addPhoneBtn" onclick="addPhone()">＋</button>
<button class="cb" onclick="resetAll()">🔄 重置</button>
<button class="cb pr" onclick="autoDemo()">▶ 自动演示</button>
```
- 8 个胶囊按钮，**只有「自动演示」有强调色**，其余 7 个完全同权
- `＋ / − / N人` 是三个独立按钮，实际是一个**步进器**却拆成三个视觉体
- 「离线模式 · 本地规则引擎」占宽最大（约 160px），却是**纯状态指示、不可点**
- 7 个按钮 + 8 个 gap = 约 640px；窄视口下换行，`flex-wrap` 一开就断成两行

**改法**（三组语义）：
| 组 | 内容 | 表现 |
|---|---|---|
| 状态 | 引擎徽标 | 收成小圆点 + 图标，hover 出说明；不占主位 |
| 步进器 | `−  3人  ＋` | **合并为一个控件**（一体化胶囊），省 2 个视觉体 |
| 操作 | 自检 / 导览 / 重置 | 次级按钮，弱化边框 |
| 主行动 | ▶ 自动演示 | 唯一强调色，右侧固定 |

预计按钮视觉体 **8 → 4**，宽度从约 640px 降到约 380px。

#### 🔴 D3 底部提示固定视口，会与手机重叠

```css
.fh{position:fixed;bottom:14px;left:50%;transform:translateX(-50%);…;z-index:5}
```
- 手机高 660 + 人名行 + 字幕条 ≈ 760px；`.wrap` 上下 padding 28px + 头部约 90px
- 在 **1080px 以下高度的窗口**里，这条 fixed 提示必然压在手机下半部分上
- 实测 1080px 截图里它紧贴手机底部、只差几像素

**改法**：去掉 `position:fixed`，改为**文档流内的状态条**（位于舞台下方），
或并进工具条下方作为第二行提示。演示时不再遮挡。

#### 🟡 D4 手机壳阴影过重，三层对比过强

```css
.pf{background:#0c0c0c; box-shadow:0 0 0 1.5px rgba(255,255,255,.1),
    0 30px 80px rgba(0,0,0,.6), 0 10px 30px rgba(0,0,0,.4), inset 0 1px 0 rgba(255,255,255,.06)}
```
- 页面底 `#08080c` → 机壳 `#0c0c0c` → 内屏 `#fff`，三重强对比
- 阴影 80px 模糊 + 0.6 透明度，在深色背景上形成"发光的黑洞"感

**改法**：机壳改 `#151517`（与底拉开一档灰）、阴影降到 `0 18px 48px rgba(0,0,0,.45)`、
内屏加 1px `rgba(0,0,0,.08)` 描边替代部分投影。

#### 🟡 D5 角色徽标与姓名被 2px 间隙拆开

```css
.pr2{font-size:10px;color:rgba(255,255,255,.3);background:rgba(255,255,255,.05);
     padding:3px 10px;border-radius:100px;margin-top:2px}
```
- 姓名（17px）与徽标（10px）之间只有 2px，且徽标自带灰底 → 视觉上"粘不住又没分开"
- 颜色 `rgba(255,255,255,.3)` 对比度过低，真实投影上几乎看不见

**改法**：`margin-top` 提到 6px（用间距 token `--s1`），徽标颜色提到 `.45`，
或干脆把身份直接放姓名后（`小明 · 发起人`）省掉一个视觉体。

#### 🟡 D6 字幕条与手机宽度不一致

```css
.cap{max-width:298px; …}     /* 手机壳宽 320px，内屏 300px */
```
- 字幕条 298px 与内屏 300px、机壳 320px **三个宽度都不一致**，左边缘对不齐
- 多台并排时三条字幕宽度随文字长短变化，基线不齐

**改法**：`.cap` 宽度对齐内屏 `300px`，`text-align:center` + `text-overflow:ellipsis` 单行省略。

#### 🟡 D7 中英文场景下 letter-spacing 取值混乱

| 元素 | letter-spacing | 问题 |
|---|---|---|
| `.hdr h1` | `-0.8px` | 中文标题负字距偏紧 |
| `.pn` | 未设 | — |
| `.pr2` | 未设 | — |
| `.app .hl` | `2.6px` | 手机内英文标签 |

**改法**：英文标签统一 `1.4px`（手机内已用此值），中文标题 `-0.4px`。

#### 🟡 D8 断网时字体整体降级

```html
<link href="https://fonts.googleapis.com/css2?family=Inter…&family=Space+Grotesk…">
```
- 断网/无外网时回退到系统无衬线字体，**标题字重与字距观感差异明显**
- 演示场景常要求离线可用，"最坏情况下的观感"必须可接受

**改法**：要么把两款字体内联（体积大），要么明确设计一套系统字体回退栈
（`-apple-system, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei'`）并**按回退字体调字距**。

#### 🟢 D9 值得保留的部分

- 黑白杂志风 + 橙色唯一强调色：方向正确，不要动
- 手机壳的物理细节（刘海 `.pn2`、侧键 `.pbt`、底部横条 `.hi`）：有质感，保留
- 暗底 + 微光晕背景（`.bg` 的 radial-gradient）：克制，保留


### 2.5 动效与细节

- 统一过渡曲线 `cubic-bezier(.4,0,.2,1)`、时长 200ms（现在 150/200/250/400/800 混用）
- 圆角收敛为 3 档：`10px`（小件）/ `16px`（卡片）/ `100px`（胶囊）
- 颜色：保持黑白杂志风，但**灰阶收敛**（现有 g100~g500 已够）

### 2.6 对比度（WCAG 2.1 AA）—— 已实施，改样式前必读

“小字看不清”除了字号，还有一半是**对比度**。实测原始令牌：

| 原用法 | 实测对比度 | 结论 | 现在怎么用 |
|---|---|---|---|
| 品牌橙 `#FF6B35` 配白字（`.btn.or` / `.cap` / `.cb.pr`） | **2.84:1** | ✗ 正文要 4.5:1 | `--pri` 只当**填充**，字色改 `--on-pri`(`#18181b`) → **6.25:1** |
| 品牌橙当**文字**（`.rco` 房间号 / `.tam` 金额 / `.ss`） | **2.84:1** | ✗ | 改用 `--pri-ink`(`#B23A0B`) → **6.00:1** |
| 次要灰 `--g400` `#a1a1aa` 在白底 | **2.58:1** | ✗ | `--g400` 改 `#71717a` → **4.88:1**；`--g500` 相应改 `#52525b` → 7.8:1 |
| 语义绿 `--grn` `#07C160`（`.bal.safe` / `.bam.pos` / `.test-ok`） | **2.16:1** | ✗ | 改 `#046B35` → **6.01:1** |
| 语义琥珀 `--amb` `#FF9500`（调整单角标 / 预算告警） | **2.20:1** | ✗ | 改 `#9A5A00` → **5.48:1** |
| 语义红 `--red` `#FA5151`（白字按钮 / 删除） | **3.30:1** | ✗ | 改 `#C64040` → 白字 **4.99:1** |
| 蓝 `--blu` `#1a73e8`（订单类型角标） | **4.08:1** | ✗ | 改 `#1557B8` → **6.16:1** |
| 输入框占位符 `.ain::placeholder`（`--g200`） | 1.14:1 | ✗ | 改 `--g300`（40px 大字，3:1 即达标） |
| `.fi::placeholder` | 浏览器默认 | 不一致 | 显式设 `--g400` |

**规则**：
- 文字颜色**一律用 `:root` 令牌**，不要再写死 hex。写死 hex 会让 `#uitest` 的对比度体检失败。
- `--pri` 是**填充色**、`--pri-ink` 是**白底上的橙字**、`--on-pri` 是**橙底上的字** —— 三者用途不要混。
- 进度条 `.bf.safe/warn/over` 的渐变是纯装饰，保留原来的鲜亮色（`#07C160` 等），**不要**跟着改成 AA 版本。
- 大字号（≥24px，或 ≥18.66px 且加粗）只需 3:1；其余文字要 4.5:1。`#uitest` 就是按这个规则逐节点算的。
- `.pbt`（机身侧键）是纯装饰，标 `aria-hidden="true"`，不参与对比度体检。

## 三、验收标准（改完必须过）

1. **间距只剩 6 档**：脚本扫描 `.app` 内所有 `margin/padding`，去重后 ≤ 6 个值
2. **字号只剩 6 级**：去重后 ≤ 6 个值，且相邻差 ≥ 2px
3. **正文最小 13px**：`grep` 不到 < 13px 的正文（标签类 ≤ 10px 需在白名单内）
4. **区块数下降**：房间页一级区块 17 → ≤ 10；stats 21 → ≤ 12
5. **窄窗口不裁切**：900px 宽下 3 台手机全部可见（已有 flex-wrap）
6. **对比度达标**：`.app` 内**全部文本节点**按字号对应的 AA 阈值逐个算对比度，无不合格项
   （已实装进 `#uitest`，见 2.6 节）
7. **键盘可达**：所有可点元素都能 Tab 到、Enter/空格能激活；弹层 `Esc` 可关且焦点不外泄
   （已实装进 `#uitest`）
8. **现有测试全绿**：尤其 `#uitest` 的排版体检（正文/标签字号阈值、主视觉 ≥30px、最大 ≤36px、无头像守卫）

## 四、实施顺序（建议）

| 阶段 | 内容 | 风险 | 状态 |
|---|---|---|---|
| **P0** | 抽 CSS 变量（间距 6 档 + 字号 6 级），**不改版式**，只把现有硬编码值吸附到最近的档位 | 低。视觉小幅变化，但立刻消除"乱" | 已实施（字号收敛进 `demo/index.html` 的「手机内排版比例」段） |
| **P1** | 按"组"重组房间页 / 统计页 / 结算页，区块数下降 | 中。需回归 `#uitest` 布局与字号断言 | 已实施 |
| **P2** | 演示台（工具条分组、手机壳、字幕条统一） | 低。不影响手机内 UI 与断言 | 已实施（工具条改「状态徽标 + 步进器 + 操作 + 主行动」） |
| **P3** | 动效曲线、圆角、灰阶收敛 | 低 | 部分实施 |
| **P4** | 对比度与键盘无障碍（2.6 节） | 中。会改动视觉观感（橙底改深色字最明显） | 已实施 |

> P0 做完就有明显改善（因为"乱"主要来自间距/字号碎），建议先做 P0+P2 给你看效果。

## 五、需要你确认的点

1. **正文从 9.5~11px 提到 13px**：信息会少放一些（每屏内容变少、滚动变长）。
   换来的是"看得清、不费眼"。是否接受？
2. **是否保留多机舞台的形式**（3~4 台手机并排）？还是更想看**单机放大版**（一台手机占满屏幕，更接近真机体验）？
3. **演示台的工具条**：8 个按钮是否砍掉一些？我建议保留 `自检 / 导览 / ＋− 人数组 / 重置 / ▶自动演示`，把「离线模式」改成图标 + 悬浮说明。
4. 上面第 4 节实施顺序是否认可？还是想一次性全做？
5. **橙底改深色字（2.6 节）观感变化最大**：`▶ 自动演示` / `📷 拍照` / 演示字幕条会从"白字橙底"变成"近黑字橙底"（对比度 2.84 → 6.25）。
   这是为了 AA 达标。若你更看重原观感，另一条路是把橙色调深到 `#C2410C` 保住白字（品牌识别度会变弱）—— 需要你选一个。
