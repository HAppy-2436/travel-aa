# ⚙️ 部署与配置

> 三件事：**网页 Demo 不需要部署** → **可选后端怎么部署** → **小程序 + 云开发怎么配**，最后是 **AI 通道怎么配**。

---

## 一、网页 Demo：无需部署

`demo/index.html` **不是自包含单文件**：它内联了 CSS/JS、把订单截图样例 base64 内嵌（`demo/assets/vision-samples.js`），
但通过 `<script src>` 引用了三份 **UMD 共享内核**（`apps/miniprogram/utils/{ai,ctrip,sync}.js`），
并从 Google Fonts 取字体（取不到自动回退系统字体）。两种用法：

1. **本地直接打开**：**整个项目目录一起拷过去**，双击 `demo/index.html` 即可（推荐，演示用）。
   只发一个 html 文件会白屏。
2. **静态托管**：放到任意静态服务器/对象存储（Nginx、GitHub Pages、OSS…）也可以，
   但**必须保持相对目录结构**（`demo/` 与 `apps/` 同级），否则三个内核脚本 404。

**两点注意**：

- `file://` 协议下浏览器禁止跨源请求 → Demo 的「AI 通道探测」会失败并显示 `🔌 离线模式`（功能不受影响）。
  若需要联网 AI 能力，把 Demo 放到 http 服务下，或按第四节配置后端。
- 同步能力（刷新不丢 / 多窗口实时）是**运行时探测**的：`localStorage` 与 `BroadcastChannel` 可用就启用，
  不可用就降级为单页联动，工具条同步徽标会如实显示当前档位（`🔗 多窗口已同步` / `💾 已开启本地留存` / `📴 单页联动`）。
  **实测 Edge/Chrome 下 `file://` 双击打开也能持久化、刷新不丢**；跨窗口同步建议用本地静态服务器打开最稳：

  ```bash
  npx serve .          # 然后访问 http://localhost:3000/demo/index.html
  # 或 python3 -m http.server 8080
  ```

  打开两个窗口访问同一地址：一个窗口记一笔，另一个窗口秒级出现；刷新任一窗口数据仍在。
  工具条上的同步徽标会显示当前处于 `🔗 多窗口已同步` / `💾 已开启本地留存` / `📴 单页联动` 哪一种。

## 二、可选后端（`server/`）

用途：给 Demo / 小程序提供房间与账单 REST 接口，以及可选的 AI 增强接口。
**不部署也不影响网页 Demo 的任何演示功能。**

### 2.1 本地运行

```bash
cd server
npm install          # 含 better-sqlite3（本机编译）
npm start            # http://localhost:3000/api/health
```

数据库文件 `server/data/travel-aa.db` 会在启动时自动创建（已在 `.gitignore` 中）。

### 2.2 服务器部署（1 核 1G 足够）

资源占用参考：内存 ~80MB、CPU < 5%、磁盘 ~50MB。

```bash
# 方式一：一键脚本
scp -r travel-aa/server/ root@你的服务器IP:/opt/travel-aa/
ssh root@你的服务器IP && cd /opt/travel-aa && bash deploy.sh

# 方式二：Docker
docker-compose up -d && docker-compose logs -f

# 方式三：PM2 手动
npm install -g pm2 && npm install --production
pm2 start ecosystem.config.js && pm2 save && pm2 startup
```

### 2.3 Nginx 反代（可选）

```bash
cp nginx.conf /etc/nginx/conf.d/travel-aa.conf
vim /etc/nginx/conf.d/travel-aa.conf      # 改成你的域名/IP
nginx -t && nginx -s reload
```

### 2.4 环境变量

复制 `server/.env.example` → `server/.env`（**不要提交**）：

```ini
PORT=3000
# 可选：AI 增强（任何 OpenAI 兼容接口）
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-flash
VISION_MODEL=deepseek-flash
DEEPSEEK_API_KEY=你的Key          # 也可用系统环境变量注入
NPU_FALLBACK=0                    # 本机端侧模型回退（可选）
```

**无 Key 行为**：服务正常启动，`/api/ai/*` 自动降级为本地规则引擎，Demo 显示离线徽标。

### 2.5 接口与自测

接口清单见 `docs/架构与实现.md` 第六节。快速自测：

```bash
curl http://localhost:3000/api/health
curl -X POST http://localhost:3000/api/rooms -H "Content-Type: application/json" \
  -d '{"userId":"test","nickname":"小明","name":"东京行","destination":"东京"}'
```

## 三、微信小程序 + 云开发

> 不配置云开发也能在小程序里跑：`apps/miniprogram/utils/db.js` 内置**演示模式**（本地造数据）。
> 下面是接真实云开发的完整步骤。

### 3.1 创建云环境

1. 微信开发者工具 → 导入项目 → 选择 `travel-aa` 根目录（`project.config.json` 已指向 `apps/miniprogram` 与 `apps/cloudfunctions`）
2. 点「云开发」→ 开通并创建环境（建议 `travel-aa-prod`）
3. 记下环境 ID，填入 `apps/miniprogram/app.js`：

```js
wx.cloud.init({ env: '你的环境ID', traceUser: true });
```

### 3.2 初始化数据库

1. 右键 `apps/cloudfunctions/initDB` → **上传并部署：云端安装依赖**
2. 云开发控制台 → 云函数 → `initDB` → **测试运行**

自动创建以下集合与索引：

| 集合 | 用途 | 索引 |
|---|---|---|
| `rooms` | 房间数据 | roomCode(唯一)、members.id + updatedAt |
| `bills` | 账单数据 | roomId + createdAt |
| `invitations` | 邀请记录 | roomCode + createdAt |

### 3.3 数据库权限

`rooms`（仅房间成员可读写）：

```json
{ "read": "auth.openid in doc.members[].id", "write": "auth.openid in doc.members[].id" }
```

`bills`（由云函数控制，客户端可读写）：

```json
{ "read": "auth.openid != null", "write": "auth.openid != null" }
```

`invitations`：

```json
{ "read": true, "write": "auth.openid != null" }
```

### 3.4 云存储规划

```
cloud://环境ID.travel-aa-prod/
├── ocr/        # 待识别图片（识别后即删）
├── bills/      # 账单凭证（可选保留）
└── avatars/    # 头像（可选）
```

### 3.5 云函数部署清单

按顺序部署（右键 → 上传并部署：云端安装依赖）：

| 顺序 | 函数 | 功能 |
|---|---|---|
| 1 | `initDB` | 初始化数据库 |
| 2 | `login` | 获取 openid |
| 3 | `createRoom` | 创建房间（生成唯一房间号） |
| 4 | `joinRoom` | 加入房间（校验房间号） |
| 5 | `addBill` | 添加账单（同步更新房间统计） |
| 6 | `deleteBill` | 删除账单 |
| 7 | `removeMember` | 移除成员（未结清不可移除） |
| 8 | `settle` | 服务端结算（多币种口径与前端一致） |
| 9 | `ocr` | 票据 OCR（需自备腾讯云 Key，见下） |

### 3.6 OCR 三种方案

| 方案 | 说明 |
|---|---|
| A. 腾讯云 OCR（推荐） | 注册腾讯云 → 开通「文字识别 OCR」→ 把 `SecretId` / `SecretKey` 填入 `apps/cloudfunctions/ocr/index.js` |
| B. 微信 OCR 插件 | 公众平台 → 设置 → 第三方设置 → 插件管理 → 添加「OCR识别」插件 |
| C. 云函数调用微信 OCR | 云函数内 `cloud.openapi.ocr.printedText({ imgUrl: fileID, type: 'photo' })` |

### 3.7 联调自测

1. 部署云函数 → 2. 运行 `initDB` → 3. 设置权限 → 4. 小程序内创建房间 → 5. 另一台手机/账号加入 → 6. 记一笔看同步 → 7. 一键结算 → 8. 上传截图测 OCR

## 四、AI 通道配置（自备 Key）

Demo 与后端的 AI 能力是**可选增强**，配置后自动启用：

1. 复制 `server/.env.example` 为 `server/.env`
2. 填任意 OpenAI 兼容服务的 `LLM_BASE_URL` / `LLM_MODEL` / `VISION_MODEL` / API Key
3. `npm start` 启动后端
4. 刷新 Demo：右上角徽标由 `🔌 离线模式` 变为 `☁️ AI 已连接`

**要求**：
- 视觉（截图识别）需要模型支持图片输入；不支持时接口会返回错误并被 Demo 捕获（提示切回内置样例）
- 没有 Key 时不要慌：规则引擎路径覆盖了全部演示功能

## 五、常见问题

| 问题 | 处理 |
|---|---|
| Demo 显示离线模式 | 正常：未启动后端或 `file://` 限制；功能不受影响 |
| 小程序创建房间报「环境不存在」 | 检查 `apps/miniprogram/app.js` 的环境 ID |
| 小程序数据不实时 | 确认使用 `watch()` 监听集合变化 |
| OCR 识别失败 | 检查腾讯云 SecretId/Key 与 OCR 服务是否开通 |
| 后端启动失败（better-sqlite3） | 需要本机编译环境（Windows 装 VS Build Tools；Linux 装 build-essential/python3） |
| 端口占用 | 改 `.env` 的 `PORT`；Demo 的探测地址是 `http://localhost:3000`，改端口后需同步修改 `demo/index.html#probeEngine` |
| 数据库文件能提交吗 | ❌ 不能。`server/data/` 与 `*.db*` 已在 `.gitignore` 中，程序会自动重建 |
