> 评审对象：当前交付形态 —— **网页版 Demo**（`demo/index.html`），评委在浏览器里直接打开。
> 评审身份：资深软件工程师 ＋ 携程产品测评官 ＋ 设计师。
> 本文件只记**真问题**与**真改动**：每条都对应一次可复现的验证，没改的也写清为什么不改。

## 一、评审方法（不是"看着感觉"）

| 手段 | 做法 | 拿到什么 |
|---|---|---|
| 逐屏实测 | 临时探针遍历 9 个页面，统一截屏（含 2× 放大取景） | 每一屏的真实排版，不靠脑补 |
| 性能实测 | 在同一页面里计时 `syncAll()` / `fitPhones()` 并数 DOM 节点 | 知道**该不该**做性能优化 |
| 真实发布实测 | 起静态服务器，按 GitHub Pages 的**子路径**方式打开 | 发布形态下是否白屏、是否 404 |
| 真实视口实测 | 1366×768（投影仪/笔记本常见）量手机底边 | 首屏是否被裁 |
| 一条命令复现 | `node tests/run-all.js` | 9 套断言是否全绿（第十二轮结束时为 861 项） |

性能实测结果（**决定了不做过度优化**）：

```
syncAll   0 ms/次        fitPhones  0 ms/次
app 节点  113–125        全页节点   389–468        账单 9 笔
```

→ 结论：**性能不是瓶颈**，本轮所有改动都是"读得懂 / 记得住"层面的，不引入任何新架构。

## 三、发现的问题与处置

### A. 可读性 —— 评委第一眼最容易扣分的地方

**A1｜同一个数字，两种写法（真缺陷）**
金额英雄区写 `¥15,966`，往下 60px 的预算进度写 `¥15966 / ¥20000`。
同一个数、同一屏、两种格式 —— 评委一眼就会觉得"没打磨"。
→ **修**：`money()` 全局统一加千分位，原先的 `moneyK` 别名指向同一个函数（不再有两套）。
涉及所有金额位（账单、余额、结算、统计、总览、导出预览）。

**A2｜标签中英混排没有规律**
同一页里既有 `集体账` 又有 `预算 / BUDGET`，还有 `BILLS`。
→ **修**：统一为 `中文 / EN` 一种写法，约 35 处：`预算 / BUDGET`、`集体账 / TOTAL`、
`笔数 / BILLS`、`成员 / MEMBERS`、`房间号 / CODE`、`最少转账 / MIN TX`、`各人收支 / BALANCES`、
`最简转账 / TRANSFERS`、`账单记录 / BILLS`、`消费统计 / REPORT`、`分类占比 / CATEGORY`、
`每日消费 / DAILY`、`入账方式 / SOURCES`、`AI 账单审计 / AUDIT`、`怎么分 / SPLIT`、
`币种 / CURRENCY`、`谁付的 / PAYER`、`买了什么 / NOTE`、`算谁的 / OWNER`、
`结清卡片 / SHARE CARD`、`AI 旅行小作文 / NARRATIVE` …
（评委区里的中文短语标签**不**加英文，避免噪声。）

**A3｜数字不等宽，列对不齐**
比例字体下 `1` 比 `8` 窄，一列金额右边缘是锯齿状。
→ **修**：所有金额 / 数字类选择器加 `font-variant-numeric: tabular-nums`
（`.bam .ba .ov .svm .tam .rsv .finale-v .ain .bnum .mbr .bal`）。

**A4｜待机态解说条写着「准备中」，其实是"没在跑"**
→ **修**：改为「待机」（浮动栏与常驻条共用同一份文案，两处同时生效）。

**A5｜房间卡金额是裸数字**
`total.toFixed(0)` 直接贴出来，无千分位、无标签。
→ **修**：改走 `money(total,0)`，并补 `账单 / BILLS`、`总消费 / TOTAL` 两个标签。

**A6｜同一类缺陷在别处还有残留（逐屏截图才发现的）**
只修"看见的那一处"是不够的。把 9 个页面全部截图后，又抓出 6 处同类问题：

| # | 现象 | 修 |
|---|---|---|
| A6-1 | 结算页同屏：主视觉 `¥13,496.00`，往下 60px 的预算行却是 `¥13,496` / `¥20000`（**千分位和小数位都不一致**） | 两处统一 `money()`（两位小数 + 千分位） |
| A6-2 | 房间详情页预算行 `¥3,374 / ¥5000 人均` | 同上 |
| A6-3 | 「结清卡片」复制到群里的文本是 `总消费 ¥13496.00`（**最容易被转发出门的一处，偏偏没千分位**） | 走 `money()` |
| A6-4 | 票据识别样例预览、OCR 结果行、批量导入按钮共 5 处 `.toFixed(2)` | 全部走 `money()`（CSV 导出**保持**裸数字，机器读友好） |
| A6-5 | 统计页 h2 `消费统计 / REPORT`，而它正上方的小标题已经是 `SPENDING REPORT` —— 英文重复了两遍 | h2 只留中文（与房间页 `ROOM DETAIL` + `国庆旅行` 的写法对齐） |
| A6-6 | 结算页底部三个格子是 `MEMBERS` / `BILLS` / `最少转账 / MIN TX`，前两个没中文 | 统一 `成员 / MEMBERS`、`笔数 / BILLS` |

**A7｜文案在窄屏被拦腰折断**
- 识别入账页的说明条原来是一行，在手机宽度下断成「…票据 携程订 / 单短信…」→ 改成**一行一个能力**。
- 账单类型五个胶囊 `微信截图 / 支付宝 / 账单列表 / 纸质小票 / 发票` 在手机上全部折成两行
  → 缩成 `微信 / 支付宝 / 账单 / 小票 / 发票`（详情由样例预览里的"微信支付截图 · 单笔交易"补足）。
- 房间页底部 `＋ 记一笔` / `📷 识别入账` 被折成两行（"识别入" + "账"）→ 加 `white-space:nowrap`，
  并按内容宽度分配 `flex`（1 / 1.4 / .85），而不是三等分。

**A8｜评委区小胶囊里出现 `/`**
`票据 / 订单截图识别`、`AI 审计 / 洞察` 这两个胶囊里的斜杠和"中文 / EN"规则撞车，会被误读成中英对照
→ 改成 `票据与订单截图识别`、`AI 审计与洞察`。

### B. 信息层次 —— 手机里"下一步点哪"要一眼看到

**B1｜底部三个按钮一样重，主操作看不出来**
改前：`记一笔`＝浅色、`拍照`＝橙色主色、`结算`＝深色。三个都在抢注意力，
而**橙色其实给了次要操作**（记一笔才是最高频动作）。
→ **修**：只保留一个主按钮（橙）＝`＋ 记一笔`；`识别入账`、`结算` 降为白底次按钮。

**B2｜「拍照」这个名字跟里面的内容不符**
点进去其实有三个页签级能力：票据识别、**携程订单**、订单截图。叫"拍照"会让评委**找不到携程订单入口**。
→ **修**：按钮正名为 **「📷 识别入账」**；自动化验收里的选择器同步改为按可见文字点击（2 处）。

**B3｜携程订单藏在页签里，进去之前不知道有**
→ **修**：在页签下方加一行说明条，把两个页签各能干什么写清楚：
`📷 票据 = 微信/支付宝/小票/发票截图 ｜ 🧳 携程订单 = 订单短信、邮件文本或订单截图`。

### C. 价值主张 —— 评委看完能不能用一句话复述

**C1｜评委区只有"我们有什么"，没有"和别家比不一样在哪"**
原来只有 12 个能力小胶囊 + 五层 AI 能力，读起来像功能清单，**没有差异化论点**。
→ **修**：新增编号卡「和常见记账软件比，三个不一样的点」：

1. **行程即账本** —— 携程订单文本直接解析成机票 / 酒店 / 门票账单，多笔勾选一次入账；订单截图也能读。
2. **算得准、也收得回** —— 分摊合计恒等于账单金额、净余额合计恒为 0；贪心给最少转账笔数；每笔可标「我转了」。
3. **旅行专属的那些小事** —— 外币按记账当时的汇率快照；抹零差额并入分摊（账不会因凑整而不平）；
   私账不进 AA 但你仍知道自己花了多少；有人离队、酒店改价可事后补一笔调整。

### D. 证据可信度

**D1｜验收数字有"写死"的嫌疑**
一张印着 `9 / 836 / 22 / 101` 的静态数字墙，评委无法判断是否真跑过。
→ **修（已有约定，本轮复核）**：`页内自检`、`交互验收` 两格**初始显示 `—`**，
只有当场点「在页面里跑一次自检」才填入真实结果；`9 套 / N 项` 是**唯一**的人工维护常量
（`SUITE_STATS`），本轮新增测试闸门盯着它与静态占位一致（占位从 835 校正为 850，
消掉首帧闪一下的错数）。

### E. 明确记录为"不做"的项

| 项 | 为什么不做 |
|---|---|
| 服务端鉴权 / 限流 / `cors` 收紧 | Demo 全程只读本地状态、不连真实后端；接口已留，接入时再收紧 |
| 小程序端跟进 V3 内核全部能力 | 本轮交付形态是网页；内核已同源，小程序接入是独立一轮 |
| 内联 Google Fonts | 字体是渐进增强，断网回落系统字体不影响功能与可读；内联收益低 |
| 未知币种 `getRate()` 回退 1 | 已在 `docs/架构与实现.md` 标注为已知取舍（宁可如实按 1:1 也不猜汇率） |
| GitHub Pages 只发 `demo/` | **不能**：demo 通过 `../apps/miniprogram/utils/*.js` 引三份 UMD 内核，只发 demo 会白屏 |

## 四、本轮要评委记住的三个创新点

1. **行程即账本**：不是"支持导入"，是**携程订单文本 = 账单**（订单号、金额、类型、出行人一次解析），
   且**订单截图**走同一条识别入账管线。
2. **账恒平 + 最少转账 + 结清闭环**：分摊合计恒等于金额、净余额合计恒为 0，有单测与页内自检双闸门；
   贪心给最少转账笔数；每笔可标「我转了」，两台手机同时看得见。
3. **旅行专属的小事**：汇率快照（按记账当时，不按今天）、一键抹零且差额并入分摊、私账（人情账）、
   多退少补、暂估改价 —— 这些都是**真实旅行会碰到、通用记账软件不管**的事。
