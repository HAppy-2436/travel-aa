# 归档：已废弃的设计方案

> ⚠️ **本目录下的文件已废弃，不参与交付，也不要在演示时打开。**

## styles/ —— 早期视觉风格探索（2024-09-23）

项目立项初期做过 4 套视觉风格的完整可交互 Demo，用于选定最终方向：

| 文件 | 风格 | 状态 |
|---|---|---|
| `styles/swiss.html` | 极简瑞士风（黑白排版） | ❌ 未采用 |
| `styles/glass.html` | 玻璃拟态 | ❌ 未采用 |
| `styles/brutal.html` | 新粗野主义 | ❌ 未采用 |
| `styles/journal.html` | 旅行手账风 | ❌ 未采用 |
| `styles/index.html` | 上述 4 套风格的选择页（内含 iframe 预览） | ❌ 未采用 |

**最终结论**：采用**黑白杂志风**（大号粗体标题 + 大写英文小标签 + 网格分割线 + 黑/白/橙）
作为产品视觉基线，其实现即当前唯一交付物 **`demo/index.html`**（由早期 `showcase.html` 与单机版 Demo 合并而来）。

## legacy/ —— 已删除的旧主 Demo

早期还有一版**单机橙色风格**的 `demo/index.html`（5 个页面、仅单设备）。

- 它的**全部功能**（AI 一句话/语音记账、多币种、票据识别、携程订单、AI 审计、统计、小作文、导览、自检）
  已合并进现 `demo/index.html`；
- 它的**视觉风格已废弃**（与选定的黑白杂志风冲突）；
- 为避免"到底该看哪个 Demo"的歧义，该文件**已删除**，不再保留副本。

> 如果确实需要回顾旧版：它的逻辑与新版一一对应（函数名基本一致），可从 git 历史或本目录的说明中了解设计意图。

## 为什么保留而不是删除

1. 保留设计决策的完整过程，方便答辩时说明"我们比较过多种方案"；
2. 后续如需换风格，这些文件可作为起点，不必从零重做。

## 注意

- 这 4 个文件的交互与数据是**早期写死的**，与主线 Demo 的算法内核不同步，**改动它们没有任何收益**；
- 它们**不引用** `apps/miniprogram/utils/` 下的共享内核，也无法接入 AI 能力，属于纯静态样例。
